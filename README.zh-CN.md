# payslate-spike-klee

一个小探索：先看 KLEE 怎样逐条走过一个批次读取函数，再测三种情况下路径数怎样增长——精简的玩具读取函数、真实转换器抽出来的读取函数、以及不受约束输入下的整支转换器，据此判断符号执行值得在哪里跑。

`toy.c` 是一个最小读取函数：一个标记字节、几个单字节金额、一个声明条数和一个声明合计，小到可以把 KLEE 报告的每一条路径都看清。

```sh
sh run.sh 1      # 在一条记录上对玩具读取函数跑 KLEE，并打印一个解出的输入
```

全部在官方 KLEE 镜像（`klee/klee:v3.2`）里运行；该镜像只有 amd64，在 Apple 芯片上通过模拟运行。不记录任何时间，重要的是路径数与测试数。

路径数对比与结论见 [FINDINGS.zh-CN.md](FINDINGS.zh-CN.md)。
